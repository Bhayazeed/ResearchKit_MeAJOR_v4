# MeAJOR v4 study protocol

## Active English/length curation workflow (2026-10-27, corrected)

This section supersedes the earlier strict phishing-screening proposal and historical defaults below. The curator determines eligibility; victim models determine predicted phishing classes.

1. Read the full original CSV and select every label-1 record, without sampling or automatic deduplication.
2. Count alphabetic words in the full body, excluding the subject. Require more than 100 words: `--min-words 101` is the inclusive implementation. Reject shorter bodies before inference.
3. Ask PPLX only whether the body is predominantly English. The model sees up to 20,000 body characters; record truncation. Do not ask the curator to judge phishing intent, legitimacy, link reputation, or independent readability criteria. No langdetect confidence threshold applies.
4. Export the accepted cohort to `outputs/quality_pplx_english_length_v3/quality_accepted.csv`. Preserve original labels, IDs, hashes and metadata, and retain an audit of every acceptance/rejection. A language judgment is not validation of phishing ground truth.
5. Evaluate the identical accepted cohort with each victim, including PPLX in its separate classifier role and other LLMs. Victim prompts use shared PHISHING/NON_PHISHING definitions. Keep NON_PHISHING predictions and failures in reporting; never use victim predictions to retroactively determine curator eligibility. Default baseline outputs are in `outputs/curated_english_length_baseline`.
6. Retain historical readability outputs unchanged. Their 31,056 accepted rows do not establish English and >100 words; 12,998 are already below 100 words. Old rejected rows must also be reconsidered because readability was a different selection criterion. The corrected full curation has not been run; its final accepted count is unknown.
7. For paper claims, distinguish dataset labels from independently verified phishing intent. Report positive-only detection, response coverage, duplicate-aware uncertainty and selection sensitivity, including the reuse of PPLX as language curator and victim. Any independent human label audit is separate from the requested eligibility rule.

Use the current README for runnable commands and current output paths. The dated sections below are historical audit context, not current launcher configuration.

## Historical label-1 workflow (2026-10-26)

This section supersedes the balanced pilot/main workflow below for the current experiment. All 48,034 supplied label-1 rows are selected by default; label 0 and the invalid label are excluded. There is no sampling or automatic deduplication in the primary input adapter. Source row positions, IDs, text hashes, and original metadata remain traceable.

1. **Define the claim first.** The current population supports detection/recall on dataset-supplied positive emails. It does not estimate false-positive rate, specificity, or representative two-class precision/F1. Accuracy on scored positive-only rows equals recall. Report `metric_scope`, `n_positive`, `n_negative`, `classification_coverage`, and both conditional recall and `detection_rate_all_positives`. The last measure counts nonresponses in its denominator without pretending they are observed negative predictions.
2. **Freeze the source and selection.** Record the source checksum and label filter. The local CSV's MD5 matches the official Zenodo record (`aa8f59e96787cbd696c0b650e5400dc9`). It has 20 columns and 108,685 records. Label-1 row IDs remain stable after filtering.
3. **Choose the analysis population before model comparison.** The current baseline launcher evaluates all 48,034 positives; it does not automatically consume accepted-only curation outputs. For an explicitly curated population, freeze the accepted rows and pass that same frozen CSV to every baseline and downstream metric command. Report retention and exclusions. Keep the full positive cohort as a separate sensitivity analysis if the main population is curated; do not merge the two experiments' checkpoints.
4. **Validate the curation decision.** The saved PPLX run contains 31,056 usable and 16,978 not-usable decisions. These are model quality judgments, not human-confirmed phishing ground truth. Review a reproducible sample across accepted/rejected decisions, sources and languages with independent raters and a defined rubric. Selecting the cohort with PPLX and then benchmarking PPLX on it is a potential selection bias; compare against an independent/human criterion or report sensitivity to the selection rule.
5. **Account for repeated observations and language.** The positive cohort has 46,842 distinct normalized subject/body hashes and 1,192 duplicate excess rows. Preserve the requested full population but report a deduplicated sensitivity analysis or uncertainty clustered by duplicate family. Near-duplicate families have not been identified. Raw language values include multi-valued strings such as `en;en`; do not interpret these as simple single-language codes. The optional old sampling prefilter recognizes only exact `en`/`english` and therefore excludes such rows; it is not part of this active full-positive workflow.
6. **Make model comparisons reproducible.** Align the classification task definitions: the chat path currently asks PHISHING/BENIGN while the decision path previously used a broader task definition (now replaced with shared PHISHING/NON_PHISHING criteria). Record the exact actual prompts/criteria, model digest and quantization, server/library versions, decoding settings, context window, and input truncation policy. Current manifests do not capture all these details. Pin the setup before collecting comparable baseline results. Temperature zero alone does not establish reproducibility across changed weights or runtimes.
7. **Disclose text limits and failures.** PPLX/JEV quality requests truncate to 20,000 characters (5 positive emails exceed this length); langdetect inspects 6,000 characters (201 exceed it). The chat baseline does not specify `num_ctx` and allows only 16 output tokens; verify actual truncation/refusal rates and record them. Do not count refusals as successful classifications or silently remove them from the main denominator.
8. **Use appropriate uncertainty and claims.** Report positive detection rates, false-negative rates, nonresponse coverage, source/language breakdowns and confidence intervals with the sampling/duplicate assumptions stated. For model comparisons, use identical row IDs and paired tests; state multiplicity treatment if testing several models. Comparing quality acceptance rates with McNemar does not establish correctness or agreement with human ground truth. Full detector performance requires a separately authorized benign evaluation cohort; the active label-1 population remains unchanged.
9. **Offline candidate analysis is a separate stage.** Existing scripts score externally supplied, reviewed candidates; no completed candidate experiment or baseline results are present in the reviewed workspace. Raw flips and similarity do not establish retained phishing intent or validated attack success. Pair the same reviewed/scored rows and disclose omissions and query budgets before making comparisons.

To freeze the PPLX-accepted label-1 cohort without sampling, after explicitly choosing it as an analysis population:


Use the same frozen CSV for actual baseline, metric and candidate commands. Omitting `--per-class` keeps every commonly accepted row. Add other complete audits to `--audit` only if their intersection is the prespecified selection rule.

Sources: [MeAJOR official release](https://zenodo.org/records/18471483), [classification metric definitions](https://scikit-learn.org/stable/modules/model_evaluation.html), [Ollama API specification](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml). Independent local verification is retained in `outputs/review_20261026/data_verification.json` and its companion script. It checks every current PPLX audit row against the source, but does not establish semantic label correctness.

## Earlier optional balanced-sample protocol

The points below describe the earlier optional sampling study, not the active label-1 default. In particular, its min-length, English and class-balancing filters are not applied to the full-positive run.

1. **Dataset provenance:** Cardoso et al. (2026), MeAJOR 2.0, Zenodo DOI 10.5281/zenodo.18471483, paper DOI 10.1016/j.dib.2026.112595. Contains anonymized subject/body and structured metadata. The user-provided 191 MB CSV has 108,685 rows (one invalid label) and TREC5/6/7 source tags only. The publication mentions Nazario and Nigerian Fraud, but these are not independently distinguishable source tags in this release. Do not claim all five sources were sampled.
2. **Gold labels:** binary 0/1 preserved, no imputation or automatic relabeling. TREC sources contain spam; dataset class 1 cannot be assumed to be manually verified credential phishing for every row. A manually annotated phishing-only subset is needed to generalize to phishing-specific attacks.
3. **Pilot/main:** 500+500 or 1500+1500 deterministic row IDs, seed 42, from the same source file. Separate pilot and main outputs, not independent folds. For independent pilot/main samples, use `--exclude` implementation or source-hash disjoint selection; do not conflate pilot metrics with main results.
4. **Input:** subject + blank line + body; length filters are computed on **body**, min 100 alphabetic words and 500 characters. Source language `en` is used as cheap prefilter; `langdetect` on shortlisted records is the second check (`english_score>=0.90`). This creates a selection bias; keep source distribution and rejected reasons.
5. **Placeholder:** retain `[URL]` and other anonymization tokens as data. Save placeholder_count/types. Preserve all original MeAJOR columns under `meajor_*` namespace, including hashed sender and URLs, but do not visit URLs.
6. **Quality:** local langdetect is language-only, not semantic coherence. PPLX system-one endpoint local 11435 and JEV via OpenRouter evaluate *usable/not_usable* and must not change the dataset gold label. A fixed cohort for all methods is required to pair quality results. JEV use transfers text to third party: review data-sharing policy before using.
7. **Baseline:** compare Qwen3.5:9B, Gemma4:E4B, PPLX, Nimble, Tev via Ollama localhost; actual model availability/tag/version must be validated. One pre-registered baseline per model. The same dataset IDs/labels for all victims. Report accuracy/precision/recall/F1 and per-source performance.
8. **Defensive perturbation analysis:** GAN and Qwen3.8 are retained as *method identifiers for externally generated, human-reviewed offline candidates*. This kit intentionally does not generate or optimize phishing messages for evasion. Analysis of user-supplied, approved candidates records raw label flips, paired McNemar, BLEU, ROUGE-L, Jaccard, content retention and optional SBERT.
9. **Reporting:** raw flip rate is not validated ASR. Human review must confirm preserved meaning and phishing content where appropriate. Only evaluate paired methods on the intersection of reviewed/scored samples, report n, omitted, and source distributions. Confidence intervals recommended.
10. **Leakage:** split/group by source and near-duplicate families before claims of generalization; row SHA256 only removes exact duplicates. Quality model selection affects cohort. Results from 3 sources cannot establish generalization to five sources.

**Security:** Do not use results to craft or distribute deceptive messages. No live URLs should be followed. Do not export CSVs to cloud APIs without explicit review of privacy terms.
